# RepoFinder product demo narration

Target length: 112 seconds

This script demos RepoFinder itself. It opens on the changed decision, then peels back to the shortest path that produced it.

## Scene 1, 0:00 to 0:09

**On screen:** The final chat answer. Highlight “Not really,” the lightweight alternatives, and the focused three-step stack.

**Narration:**

“This is the moment RepoFinder becomes more useful than a list of popular repositories. I asked for something lighter, and it changed the recommendation.”

## Scene 2, 0:09 to 0:17

**On screen:** A simple statement, then four stars move behind it and fade.

**Narration:**

“GitHub stars tell me what is popular. They do not tell me what fits my project, my goal, or the way I want to work.”

## Scene 3, 0:17 to 0:27

**On screen:** RepoFinder starting screen. Arrows point to the project and goal fields.

**Narration:**

“I start with a real project, the OpenAI Node SDK, and a concrete goal, production evaluations.”

## Scene 4, 0:27 to 0:34

**On screen:** The “Try this combination” button receives a blue pulse and click indicator.

**Narration:**

“One action sends both pieces of context to RepoFinder.”

## Scene 5, 0:34 to 0:45

**On screen:** Results view. Highlight “OpenAI ranked 4 candidates,” then the repository cards and live signal row.

**Narration:**

“It searches live GitHub data, then OpenAI ranks the candidates for this task. The result is an evidence-backed starting point, not a generic popularity contest.”

## Scene 6, 0:45 to 0:55

**On screen:** Zoom into a recommendation card. Highlight What, Why, How, Ease, Impact, and the updated, commit, contributor, and fork signals.

**Narration:**

“Each result explains what the repository does, why it fits, how I could use it, and the likely ease and impact. Current GitHub signals stay visible beside the reasoning.”

## Scene 7, 0:55 to 1:05

**On screen:** Arrow to “Ask OpenAI about this repo,” then reveal the chat.

**Narration:**

“The shortlist gets me oriented. The conversation helps me decide. I can open any result and ask how to test it in one afternoon.”

## Scene 8, 1:05 to 1:16

**On screen:** First chat answer. Highlight the ordered test plan and the fit and tradeoffs section.

**Narration:**

“RepoFinder turns the recommendation into a practical experiment, including what to try first, what to measure, and where the tradeoffs are.”

## Scene 9, 1:16 to 1:27

**On screen:** A question card appears over the chat: “I like the evaluation and monitoring idea, but do you have something more like a lightweight TypeScript library I can add directly to openai-node?”

**Narration:**

“Then I add the part a star count cannot know. I like the idea, but I want a lightweight TypeScript library that fits directly into openai-node.”

## Scene 10, 1:27 to 1:40

**On screen:** Return to the final answer. Draw attention to the honest mismatch, lighter alternatives, and focused stack.

**Narration:**

“It acknowledges that the original result is too heavy, offers lighter alternatives, and gives me a focused next step. My taste and constraints changed the answer.”

## Scene 11, 1:40 to 1:52

**On screen:** Split path. A human uses the browser and chat. An agent calls `recommend_repos` through MCP and receives structured recommendations.

**Narration:**

“A person can explore and refine recommendations in the browser. An agent can call the same recommendation capability through MCP and receive structured results it can use in its own workflow.”

## Scene 12, 1:52 to 2:00

**On screen:** Product flow diagram resolves into the RepoFinder wordmark and URL.

**Narration:**

“RepoFinder helps humans and agents move forward with evidence, context, and individual taste. Build better, focused, and faster.”

## Pronunciation notes

- RepoFinder: “repo finder”
- GitHub: “git hub”
- openai-node: “open A I node”
- MCP: say each letter, “M C P”
- TypeScript: “type script”
